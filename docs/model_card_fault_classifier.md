# Model Card – XGBoost Fault Classifier (W7)

## Intended Use
- **Scope:** Demonstration of fault‑type classification within the NetSentinel NOC AIOps demo.  
- **Audience:** NOC engineers, demo participants, and developers of the demo environment.  
- **Usage:** Called via the `ml-service` `/predict` endpoint (or through the API gateway) to obtain a fault type, confidence score, and per‑class probabilities for an enriched alarm.  

## Data
- **Source:** Synthetic data generated by `synth_faults.py`.  
- **Size:** 3,000 labelled alarm instances (seed 42).  
- **Split:** Time‑based; earlier timestamps for training, later timestamps for testing.  
- **Features (29):**  
  - Alarm severity (numeric)  
  - One‑hot encoded node type (e.g., `router`, `switch`)  
  - Topology blast radius (numeric)  
  - Deduplication count (numeric)  
  - KPI context values (numeric)  
  - Alarm‑group size (numeric)  
  - … (other engineered numeric descriptors)  
- **Leakage protection:** Root‑cause labels (`LEAKY_FIELDS`) are excluded from the feature vector; a unit test enforces this.  

## Model Details
- **Algorithm:** XGBoost (CPU) – gradient‑boosted decision trees.  
- **Parameters:** Small model (max_depth = 5, n_estimators = 100, learning_rate = 0.1).  
- **Versioning:** Stored under `$MODELS_DIR/fault_classifier/v<UTC timestamp>/model.json` + `meta.json`. Registry entry in `models/registry.json`.  

## Metrics (Synthetic Hold‑out)
| Metric          | Value |
|-----------------|-------|
| Accuracy        | 0.84 |
| Macro‑F1        | 0.84 |
| Dataset size (train+test) | 3000 |

*All metrics are computed on synthetic data only; no real‑network validation has been performed.*

## Limitations
- **Synthetic only:** The model has never seen real alarm traffic; performance on production data is unknown.  
- **Feature leakage guard:** If future feature engineering inadvertently re‑introduces root‑cause information, the leakage test must be updated.  
- **Resource constraints:** Designed for a 256 MiB container; larger models will not fit.  

## Ethical & Operational Notes
- **No real‑world decisions:** The classifier is for demo visualization; it must not be used for automated remediation in a live network.  
- **Explainability:** SHAP contributions are provided via TreeSHAP; they are approximations of feature impact on the model’s output.  
- **Model freshness:** With `AUTO_TRAIN=1`, a minimal model is auto‑trained on the first /predict or /explain request if none is registered. For reproducible results, register a model explicitly via `make ml-train-xgb`.
